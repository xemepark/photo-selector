# 小日子寫真館（選片工具）

專為攝影師「選片」設計的照片瀏覽工具（Rust + Tauri 2）：打開上萬張的資料夾不卡、純鍵盤評分，
並自動抓出**閉眼、模糊、主體失焦**的照片。新生兒寫真可切換成「忽略閉眼」模式。

> 小日子寫真館 <https://smallday.tw> 的選片工具。獨立開發，與 Adobe 無關。

## 在 Mac 上安裝

1. 直接下載最新測試版：<https://github.com/xemepark/photo-selector/releases/download/beta/Photo-Selector-mac-universal.dmg>
   （或到 GitHub 的 **Actions** 分頁 → 最新一次成功的「Build macOS」→ 頁面最下方 **Artifacts**
   下載 `Photo-Selector-macOS`（是 zip，解壓後得到 `.dmg`）。正式版本則到 **Releases** 下載。
2. 打開 `.dmg`，把 **小日子寫真館** 拖進「應用程式」資料夾。
3. 第一次開啟：因為還沒有 Apple 開發者簽署，macOS 會說「無法驗證開發者」。
   - 先按「完成」關掉提示，打開 **系統設定 → 隱私權與安全性**，往下捲找到 小日子寫真館，按 **「強制打開」**，再輸入密碼確認。
   - 或在「終端機」執行：`xattr -dr com.apple.quarantine "/Applications/小日子寫真館.app"`
   - 只有第一次需要，之後直接開啟即可。
4. 開啟照片資料夾時，macOS 可能會詢問是否允許存取「圖片」、「桌面」或外接硬碟，請按「允許」。

- 支援 macOS 11 Big Sur 以上，Apple Silicon（M1–M4）與 Intel Mac 都能用（通用版）。
- Mac 上的快捷鍵用 ⌘ 取代 Ctrl：⌘O 開啟資料夾、⌘↑ 上一層、⌘A 全選、⌘R 選片分析。

### 自動編譯

`.github/workflows/build-macos.yml` 會在每次推送時，用 GitHub 的 Mac 主機編譯通用版 `.dmg`
（公開 repo 免費）。推送 `v` 開頭的標籤（例如 `git tag v0.2.0 && git push --tags`）會自動建立 Release。

### 正式簽署（選用，免除第一次開啟的警告）

需要 Apple Developer Program 會員（每年 USD 99）。在 repo 的 **Settings → Secrets and variables → Actions** 加入：

| Secret | 內容 |
|---|---|
| `APPLE_CERTIFICATE` | 「Developer ID Application」憑證匯出的 .p12，以 base64 編碼（`base64 -i cert.p12`） |
| `APPLE_CERTIFICATE_PASSWORD` | .p12 的密碼 |
| `APPLE_SIGNING_IDENTITY` | 例如 `Developer ID Application: Your Name (TEAMID)` |
| `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID` | 公證用：Apple ID、App 專用密碼、Team ID |

設定後下一次編譯就會自動正式簽署並送 Apple 公證，使用者下載後可直接開啟。

## 完全離線使用

本軟體**安裝與使用都不需要網路**，照片不會上傳到任何地方：

- 介面、字型、AI 模型（人臉 / 閉眼偵測）全部打包在執行檔內，所有分析都在本機完成。
- 沒有自動更新、沒有使用統計、沒有任何網路相關的套件。
- 介面設定了嚴格的內容安全政策（CSP），從程式層面禁止連到任何外部網址。
- macOS 使用系統內建的 WebKit，安裝檔只有程式本身，不需要下載任何元件。
- Windows 安裝檔內含 WebView2 離線安裝程式（`offlineInstaller`），沒有網路的電腦也能安裝
  （安裝檔因此會多約 130 MB）。Linux 使用系統內建的 WebKitGTK。

已驗證：清空快取後，在完全斷網（Linux network namespace）的環境啟動正式版，縮圖、選片分析、
閉眼偵測、人臉框、100% 放大、評分寫入 XMP 皆正常運作。

> 只有「開發 / 編譯」時需要網路下載套件（npm、crates.io）。若要在離線電腦上編譯，
> 可先在有網路的電腦執行 `cargo vendor` 與 `npm ci` 後連同資料夾一起帶過去。

## 開發環境

需求：Rust（stable）、Node.js 18+，以及 Tauri 的系統套件
（Linux 需要 `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev`，見 <https://tauri.app/start/prerequisites/>）。

```bash
npm install
npm run tauri dev                       # 開發模式
npm run tauri dev -- -- /path/to/photos # 啟動時直接開某個資料夾
npm run tauri build                     # 打包安裝檔（在哪個系統編譯就產生哪個系統的安裝檔）
cargo test --manifest-path src-tauri/Cargo.toml   # 後端單元測試
```

## 選片分析（v0.2，目前已停用）

> 依需求暫時從介面移除（按鈕、拍攝類型、排序與選單項目）。後端程式仍保留，日後需要時可再開啟。

開啟資料夾後會在背景自動分析（也可以按工具列的「選片分析」），每張照片檢查：

| 檢查項目 | 標記 | 說明 |
|---|---|---|
| 閉眼 | 🟥 `閉眼` / `閉眼 2/6` | 只抓**幾乎完全閉上**的眼睛：兩眼的眨眼分數都要高、眼睛長寬比都要很小（笑瞇眼、低頭不會被抓） |
| 眼睛失焦 | 🟥 `眼睛失焦` | 主角（最大的臉）**靠近鏡頭那隻眼睛**沒有對到焦。用約 4000px 的高解析度影像裁出眼睛判斷，背景模糊不影響 |
| 模糊 | 🟥 `模糊` | 沒有人臉（或臉太小）的照片，改看整張照片是否手震 / 失焦 |

- 左側「選片建議」可直接篩出 **建議淘汰** / **需要確認** / **沒有問題**；也能依「眼睛」、「清晰度」篩選。
- 「將建議淘汰標為拒絕」一鍵把有問題、且**尚未評分**的照片標為拒絕（已評星的不會被動到）。
- 全螢幕預覽（Space）會在每張臉上畫框（紅＝閉眼），並用虛線圈出「判斷對焦的那隻眼睛」（綠＝對焦、紅＝失焦）；按 **F** 開關。

### 拍攝類型：新生兒模式

工具列「拍攝類型」選 **新生兒（忽略閉眼）** 時，不再標記閉眼 / 半閉眼（新生兒大多在睡覺），
但**仍會檢查眼睛是否對到焦**（寶寶的眼睛 / 睫毛有沒有對到焦依然重要）。設定會依資料夾記住，
新的資料夾預設沿用上次的選擇。切換模式是即時的，不需要重新分析。

### 運作原理

1. **人臉偵測**：MediaPipe BlazeFace。原模型只擅長近距離大臉，所以把照片切成多層互相重疊的方塊
   （整張 → 短邊 → 1/2 → 1/4）分別偵測，再以加權 NMS 合併——合照裡的小臉也找得到。
2. **誤判過濾**：偵測器分數與特徵點模型的「是否為臉」分數都要夠高才採用（可排除金屬罐、圖案等）。
3. **閉眼分數**：依兩眼連線把臉轉正、裁成 256×256，取得 478 個特徵點，再交給 blendshape 模型
   算出 `eyeBlinkLeft / eyeBlinkRight`。兩眼平均 ≥ 0.45 為閉眼、≥ 0.28 為半閉。
   比傳統的眼睛長寬比（EAR）更能分辨「閉眼」與「側臉、低頭」。
4. **清晰度**：整張用分區拉普拉斯變異數；主角臉部則裁出臉部、縮放到固定大小後計算。
   兩者都採**相對門檻**：低於該資料夾中位數的 35% 才標記，不受相機、場景差異影響。
5. 推論使用純 Rust 的 [tract](https://github.com/sonos/tract)，模型內嵌在執行檔中，不需安裝任何額外元件。
   結果存入 SQLite 快取，重新開啟資料夾不必重算。

### 驗證結果

用一張 6 人合照（含大笑瞇眼、低頭看牌）比對 MediaPipe 官方 Python 版：

| 人物狀態 | 官方版分數（左 / 右） | 本程式 | 判定 |
|---|---|---|---|
| 笑到眼睛幾乎閉上 | 0.62 / 0.55 | 0.65 / 0.50 | 閉眼 ✓ |
| 大笑瞇眼 | 0.66 / 0.31 | 0.70 / 0.29 | 閉眼 ✓ |
| 低頭看牌 | 0.36 / 0.34 | 0.45 / 0.42 | 半閉 ✓ |
| 其餘三人睜眼 | < 0.25 | < 0.23 | 睜眼 ✓ |

官方版的偵測器在這張合照裡找不到任何臉；本程式的分層偵測找到全部 6 張。
效能：每張照片約 0.8 秒（單核心，2048px），多核心並行處理，估計 1000 張約 2–3 分鐘（8 核心，尚未用大量實拍照片實測）。

> 判斷是輔助性質，不會自動刪除或拒絕任何照片。門檻是依少量樣本調整的，實際拍攝資料若有誤判，
> 可調整 `src-tauri/src/face.rs` 的 `CLOSED_THRESHOLD` / `HALF_THRESHOLD`。

## 與 Adobe Bridge 一致的評等與色彩標籤

| 檔案 | 寫入位置（與 Bridge 相同） |
|---|---|
| RAW（CR3、NEF、ARW…） | 附屬檔 `IMG_0001.xmp` |
| JPEG | **JPEG 檔案本身**的 XMP 區段（Bridge 對 JPEG 只讀這裡） |
| RAW + JPEG 配對 | 兩邊都寫 |

- 只會改動 `xmp:Rating` 與 `xmp:Label`，檔案裡其他 XMP（Camera Raw 調整、版權、關鍵字）與影像資料完全不動。
- 新寫入的 XMP 預留空白，之後修改評等只需原地覆寫幾 KB（22MB 的 JPEG：第一次約 0.09 秒，之後約 0.005 秒）。
  第一次寫入會先寫完整暫存檔再覆寫原檔，當機也不會毀損；並保留 Finder 標籤、建立日期等檔案屬性。
  相機 JPEG 內嵌的預覽（MPF）位置會自動修正，不會失效。
- **色彩標籤是靠「名稱」對應顏色**：Bridge 預設名稱是 Select / Second / Approved / Review / To Do。
  若你在 Bridge 的「偏好設定 → 標籤」改過名稱，請在左側「標籤名稱（與 Bridge 一致）…」設定相同名稱。
  讀取時也認得 Lightroom（Red / Yellow…）與中文顏色名稱。
- 拒絕（X）寫成 `xmp:Rating="-1"`，Bridge 會顯示為「拒絕」。
- 尚未支援寫入 DNG / TIFF / PSD / PNG 檔案本身的 XMP（這些格式目前寫附屬檔，Bridge 不會讀取）。

## 檔案管理

- **資料夾樹**（仿 Bridge「檔案夾」面板）：左側常駐「常用」（家目錄、桌面、下載項目、圖片）與「裝置」（所有磁碟與外接硬碟）。
  點箭頭展開 / 收合（展開時才讀取，外接硬碟也不卡），點名稱開啟資料夾；切換資料夾時樹維持原狀，
  目前資料夾會反白並自動展開到它的位置。新增資料夾或插上外接硬碟後按「↻ 重新整理」。
- 左側欄最上方的「小日子寫真館 / https://smallday.tw」點一下會用瀏覽器開啟網站（Mac 選單也有「前往 smallday.tw」）。
- 工具列的「裁切輸出」會用瀏覽器開啟 <https://xemepark.github.io/crop/>（Mac 選單也有）。
- **複製 / 移動完成的提示訊息**會停留數秒（預設 4 秒，可在左側「提示訊息停留」設定），
  訊息上有「在 Finder 中開啟」按鈕，點了直接開啟目的地資料夾；滑鼠停在訊息上時會暫停倒數。
- **路徑列可以直接編輯**：點一下（或 ⇧⌘G）貼上 / 輸入路徑後按 Enter 前往；可用 `~`、可貼上帶引號的路徑。
  貼上的是照片路徑時，會開啟所在資料夾並選取那張照片。
- **第一次安裝的預設值**：第一次啟動自動開啟「下載項目」；左側篩選預設不顯示「相機」「鏡頭」（可在系統設定打開）；複製 / 移動到其他資料夾預設套用調整；幻燈片每張預設 2 秒。之後改過的設定會被記住
- **iCloud 上的照片**：macOS「最佳化 Mac 儲存空間」只留在雲端的照片（檔案為空殼），縮圖顯示雲朵與「☁ iCloud」標記，不會自動讀取（避免一次觸發大量下載、卡住其他縮圖），中繼資料也先略過；選取後按右鍵「從 iCloud 下載」在背景下載，下載好的照片自動換上縮圖，全部完成後重新讀取資料夾。全螢幕檢視雲端照片時會下載那一張
- **含子資料夾**：工具列「排序」旁勾選「含子資料夾」，把目前資料夾底下所有子資料夾裡的照片一起顯示（仿 Bridge「顯示子資料夾中的項目」，略過隱藏資料夾與 .app、照片圖庫等套件，最多 20000 項）。滑鼠停在縮圖上與狀態列會顯示照片所在的子資料夾；勾選時不顯示資料夾格子。每個分頁各自記住；建資料夾 / 建文字檔仍建立在目前開啟的資料夾
- **資料夾**：目前資料夾裡的子資料夾以資料夾圖示排在縮圖區最前面（有相機、鏡頭、調整等照片專屬的篩選條件時隱藏）。按兩下在目前的分頁開啟（路徑列同步更新）；右鍵可「在新分頁開啟」「在 Finder 中開啟」「重新命名…」「新增資料夾…」。資料夾重新命名：縮圖區的資料夾（右鍵或選取後按 F2）、分頁上按右鍵「重新命名資料夾…」（改目前分頁的資料夾）、左側資料夾樹按右鍵「重新命名…」；開著它的分頁會跟著換成新名稱，評等與標籤跟著資料夾走。左側「動作」的「建資料夾」在目前的資料夾建立子資料夾。縮圖區或左側資料夾樹的資料夾都可以按住拖到上方分頁列的「＋」（會反白）放開，用新分頁開啟該資料夾。把照片或文字檔拖到縮圖區的子資料夾上（資料夾會反白）放開，會問要「複製到這裡」或「移動到這裡」（與拖到分頁相同）。資料夾也能評等與加標籤（仿 Bridge）：點選資料夾後按 0–5 / X / 6–9，星等與顏色點顯示在資料夾圖示下方，左側「評等」「標籤」「檔案類型（資料夾）」篩選也會計入資料夾；設定存在資料夾裡的隱藏檔 .photoselector-folder.xmp（跟著資料夾移動，只有本程式讀得到）。點選資料夾後按 ⌫ / Delete（或右鍵「移到垃圾桶」）可把資料夾連同裡面的檔案移到垃圾桶，確認方式與刪除照片相同。資料夾不見時（在別的分頁刪除、在 Finder 刪除或改名、外接硬碟沒接上）：開著它的分頁改顯示最近一層還存在的上層資料夾並提示；連上層都找不到（例如外接硬碟拔掉）時顯示「找不到資料夾」的空白畫面，不會顯示別的資料夾的照片，接回後切回分頁即可正常開啟
- **文字檔（.txt / .md / .rtf）**：和照片一起顯示在縮圖格，縮圖是一張印著開頭內容的白紙（右下角標示格式）；左側「檔案類型」勾選「文字」可只顯示文字檔。按空白鍵預覽完整內容（可捲動，← → 照常切換），按兩下（或右鍵「編輯文字…」、預覽右下角「編輯文字」）用內建的簡易編輯器修改，⌘S 儲存、Esc 關閉（有未儲存的修改會先詢問）。左側「動作」的「建文字檔」在目前的資料夾建立新檔（可選 .txt / .md / .rtf）。RTF（例如 macOS「文字編輯」存的）中文以 \uN 或 Big5 / GBK 等字元集編碼都讀得出來；在內建編輯器存檔後只保留文字（粗體、顏色等格式會移除）。文字檔也能評等、加標籤（存在 檔名.txt.xmp 附屬檔）、複製、移動、改名、打包；調整、旋轉、影像轉存會略過文字檔
- **HEIC（iPhone 照片）**：用 macOS 內建的 sips 轉成 JPEG 後顯示（保留 Display P3 色彩與 EXIF，轉一次後快取）；可縮圖、看大圖、調整、轉存
- **透明 PNG**：透明的地方疊在白底上顯示（不再出現花掉的顏色）
- **左側欄收合**：評等以外的篩選組（標籤、調整、檔案類型、相機、鏡頭）與資料夾都可以點標題收合，收合狀態會記住；收合的組有勾選時，標題旁顯示勾選數量
- **加入時間排序**：排序多了「加入時間」，等同 Finder 的「加入日期」（檔案放進這個資料夾的時間），方便找出最近才拷貝進來的照片
- **分頁**：縮圖上方的分頁列可以同時開多個資料夾。按「＋」或 ⌘T 開新分頁（先開同一個資料夾，再換到別的資料夾）；在資料夾樹 ⌘ + 點資料夾直接用新分頁開啟；從 Finder 一次拖入多個資料夾會各開一個分頁。點分頁切換，⌘1–9 跳到第幾個，⇧⌘[ / ⇧⌘] 上一個 / 下一個；⌘W 或分頁上的 ✕（或中鍵）關閉分頁，⌥⌘W、分頁列「＋」右邊的小按鈕（或在分頁上按右鍵「關閉其他分頁」）關閉其他分頁、只留下目前（或右鍵點的）那一個，關閉視窗改為 ⇧⌘W。每個分頁各自記住選取、焦點、篩選、排序與捲動位置，切回來時還原；分頁清單下次開啟沿用。把縮圖拖到另一個分頁上（分頁會反白）放開，選「複製到這裡」或「移動到這裡」，就會複製 / 移動到那個分頁的資料夾（依系統設定套用調整）
- **從 Finder 拖入資料夾**：把資料夾直接拖進視窗，路徑列會換成該資料夾並顯示所有照片縮圖；拖入的是照片檔，則開啟所在資料夾並選取那張。
- **狀態列檔案資訊**：點選縮圖後，最下方顯示檔案格式（RAW+JPEG 顯示兩者）、相機品牌與型號（讀得到 EXIF 時）、長 × 寬、檔案大小、建立時間、修改時間與色彩空間（讀 ICC 描述檔名稱，沒有時依 EXIF 判斷 sRGB / Adobe RGB）。
- **重新整理 / 重新產生縮圖**：工具列 ⟳、⌘R 或 F5 重新讀取資料夾（新增、變更的檔案），保留選取、篩選與捲動位置；縮圖異常時，選取後按右鍵「重新產生縮圖」會刪除快取、從原檔重新產生。
- **篩選「調整」**：左側篩選可勾「已調整 / 未調整」，一次列出用「調整」改過的照片（只要資料夾裡有調整過的照片就會出現這一組）。
- **排序**：檔名、拍攝時間、修改時間、評等、檔案大小（可切換升冪 / 降冪）。
- **照片調整**（工具列「◐ 調整」、右鍵選單或 E，仿 Camera Raw）：曝光度、對比、亮部、陰影、白色、黑色、色溫、色調、細節飽和度、飽和度、HSL（紅、橙、黃、綠、水綠、藍、紫、洋紅 8 個色彩各自的色相 / 飽和度 / 明亮度），以及點曲線（RGB）。
  - 版面仿 Camera Raw：中間大圖、下方編輯中照片的縮圖列（點選切換）、右上色階分布圖（滑到黑色 / 陰影 / 曝光度 / 亮部 / 白色區域左右拖曳即可調整）
  - 修補（「修補」區塊或按 B，仿 Camera Raw 的移除 / 修復 / 仿製）：在照片上點一下或塗抹要處理的地方。「移除」只有大小設定，點下去會自動擴大範圍蓋住整個物體（花瓣、灰塵），再用內容感知合成（PatchMatch，與 Camera Raw 加入 AI 之前的內容感知相同原理）：從周圍許多 7×7 小區塊由粗到細拼出與四周圖樣最融合的內容（不顯示來源）；「修復」用旁邊的紋理覆蓋、顏色明暗自動融合；「仿製」原樣複製（這兩種有羽化設定，來源可拖曳）。大小用 [ 變小、] 變大。點選某筆修補後出現「已選取」：可改填滿方式（移除 / 修復 / 仿製）、不透明度、「重新整理」換一種合成結果（修復 / 仿製則換一個取樣的地方）、垃圾桶刪除；⌘ + 在空白處拖曳（與 Camera Raw 相同）＝按下的地方是要修的位置、拖到哪裡就從哪裡取樣，⌘ + 拖曳已選取的修補＝替它換來源；按 / 換一個來源（等於「重新整理」）；⇧ + 點一下＝從上一筆修補的終點畫一條直線（修電線、刮痕）。標題的眼睛圖示暫時隱藏修補效果比較前後。畫面上每筆修補顯示工具圖示（選取中是藍色），滑過或選取時顯示外框；游標是有刻度和中心十字的圓。「顯現汙點」把照片變成黑白高對比，容易找到灰塵；「顯示覆蓋」可關掉標示。修補存在 XMP sd:Spots；離線運作，不使用生成式 AI。同步時「修補」預設不勾
  - 裁切（「裁切」區塊或按 C，仿 Camera Raw）：裁切框維持正向、照片在下面轉；拖曳框角 / 邊調整大小，框內拖曳移動，框外拖曳旋轉（±45°），也可用「角度」滑桿或拉直工具（沿著應該水平或垂直的線拖曳）；比例可選原始比例、不限制、1:1、4:5、5:7、2:3、3:4、16:9，X 或互換圖示切換直式 / 橫式。雙擊框內或 Enter 套用、Esc 取消。裁切框永遠不會超出照片。非破壞性（存在 XMP sd:Crop），縮圖、預覽、轉存、複製 / 移動、打包都套用；[ ] 旋轉照片時裁切框跟著轉。同步到多張照片時「裁切」是一個勾選項目（以相對位置套用，比例不同的照片會自動縮到放得下）
  - 滴管（區塊標題右側的小滴管圖示）：「顏色」的白平衡滴管（I）點選照片中應該是白色或灰色的地方，自動算出色溫與色調讓它變成中性灰（可連續點不同地方比較）；「HSL」的目標調整滴管（T）在照片上按住某個顏色往上 / 往下拖，直接調整目前分頁（色相 / 飽和度 / 明亮度）中那個顏色，介於兩個色彩之間時兩邊依比例一起調。Esc 結束滴管
  - 目標調整浮動工具列（仿 Camera Raw）：曲線或 HSL 目標調整開啟時，照片左下角出現小工具列，可切換「曲線 / HSL」、HSL 的「色相 / 飽和度 / 明度」，✕ 結束，左邊握把可拖曳移動。曲線與 HSL 的按鈕使用目標調整圖示（十字 + 靶心），白平衡維持滴管
  - 曲線目標調整：「曲線」標題的小滴管，在照片上按住某處往上拖變亮、往下拖變暗（自動在那個亮度加控制點）。滑到照片上時游標會變：白平衡是滴管、曲線是上下箭頭、HSL 是左右箭頭（左右拖曳調整）
  - HSL：獨立的收合區塊，用「色相 / 飽和度 / 明亮度」分頁切換，每頁 8 個色彩滑桿（滑桿底色顯示調整方向）；雙擊色彩名稱歸零。同步到其他照片時「HSL」是一個勾選項目
  - 曲線：點一下加點、拖曳調整、雙擊或拖出框外刪除，背景顯示亮度分布
  - 右側由上到下是「曲線」、「亮度」（曝光度～黑色）、「顏色」（色溫、色調、細節飽和度、飽和度）、「HSL」、「修補」、「裁切」；面板寬度可以拖左邊緣調整（220–480 像素，雙擊恢復預設，會記住）。各區塊，可以分別點標題收合 / 展開；每個區塊標題右側有小小的重設圖示，只把該區塊歸零（有調整時圖示變橘色），狀態會記住，下次開啟調整視窗沿用；收合的區塊若有調整，標題旁會顯示橘色圓點。色階分布圖固定顯示，不收合
  - 多張同時調整（仿 Camera Raw）：在下方縮圖列 ⌘ / ⇧ 點選或 ⌘A 選取多張後，改了哪個項目就同步到所有選取的照片（只改那個項目，其他保留各自的值），約 0.35 秒後寫檔並更新縮圖；按「取消」會把其他照片還原
  - 只帶入選取的照片：只選一張就只開那一張；多選時開選取的那幾張（下方縮圖列只顯示這些）
  - WebGL 即時預覽；← → 切換照片（自動儲存）、\ 切換調整前 / 後、雙擊項目名稱歸零、在下方縮圖列 ⌘ / ⇧ 點選要一起套用的照片（⌘A 全選），按「套用到選取的 N 張照片」同步（可勾選只同步某幾項，沒勾的保留各張原本的值）
  - 非破壞性：設定寫在 XMP（自訂命名空間 sd:，RAW 寫附屬檔、JPEG 寫檔案內嵌，與評等相同），原始影像不動；縮圖、全螢幕、影像轉存都會套用，縮圖左上角顯示「調整」
  - 複製 / 移動、批次重新命名（改名後移到 / 拷貝）、拖曳到其他程式時都會套用調整（系統設定可個別開關，預設開啟；拖曳用的檔案在選取時先於背景準備好，檔名不變）：有調整的 JPEG / 影像在目的地輸出已套用調整的檔案（保留 EXIF、ICC、XMP 評等標籤，移除調整設定避免重複套用）；移動時原本未調整的原檔移到垃圾桶。RAW 無法寫入調整，照原樣複製並帶著附屬檔（RAW+JPEG 時 JPEG 套用、附屬檔的調整移除）
  - 只有 RAW 的照片是調整 RAW 內嵌的預覽圖
- **影像轉存**（工具列、右鍵選單或 ⇧⌘E，仿 Photoshop / Bridge「影像處理器」）：選取的照片另存為 JPEG（品質 0–12，與 Photoshop 相同）、TIFF（可 LZW 壓縮）、PNG，每種格式可各自「重新調整尺寸以符合」寬 × 高（不放大）。
  - 儲存至相同位置或指定資料夾，與 Photoshop 一樣建立 JPEG / TIFF / PNG 子資料夾；同名檔案不覆蓋，自動加 -1、-2…
  - 可「將描述檔轉換為 sRGB」（讀取原圖 ICC；相機設 Adobe RGB 卻沒嵌描述檔時依 EXIF 判斷）與「包含 ICC 描述檔」（sRGB 使用相容性最好的 ICC v2）
  - 保留 EXIF（方向改為正常，因為影像已轉正）；評等、標籤與「版權資訊」寫入 XMP
  - RAW+JPEG 使用相機 JPEG；只有 RAW 時使用 RAW 內嵌的相機預覽圖（尚未套用 Camera Raw 調整）
- **旋轉**：縮圖或全螢幕時按 [ 逆時針、] 順時針旋轉 90°（可多選，右鍵選單也有），立即存回原檔、縮圖同步更新。JPEG 改寫 EXIF 方向（不重新壓縮、畫質不變；沒有 EXIF 時插入只含方向的 EXIF），RAW 寫入附屬檔 tiff:Orientation（與 Bridge / Camera Raw 相同）。
- **壓縮打包**（工具列、右鍵選單或 ⇧⌘K）：選取的照片打包成一個 ZIP（預設檔名「資料夾名_日期.zip」）。有調整的照片放入套用調整後的版本（系統設定可關）；可選擇是否包含 RAW（只有 RAW 的照片一律放 RAW）；JPEG / RAW 以儲存方式放入（快、不損畫質），先寫 .part 暫存檔、完成才改名。
- **拖曳到其他程式**：選取一張或多張縮圖後直接拖到 Finder、LINE、瀏覽器上傳欄、Photoshop 等（複製，不會移動原檔）。在多選中的某張上按下時會保留整組選取；RAW+JPEG 預設只拖出 JPEG，可在左側「動作」勾選「拖曳到其他程式時包含 RAW」。
- **右鍵選單**：在 Finder 中顯示、重新命名（F2）、批次重新命名、複製 / 移動到…、移到垃圾桶。
- **重新命名**：RAW + JPEG 配對與 .xmp 附屬檔一起改名，副檔名不變；縮圖與分析快取沿用。
- **批次重新命名**（工具列「批次命名」或 ⇧⌘R，仿 Bridge）：
  - 預設集：儲存 / 套用 / 刪除常用的命名規則
  - 目的地：在相同資料夾重新命名、改名後移到其他資料夾、改名後拷貝到其他資料夾
  - 命名規則可自由增減：文字、順序編號（起始值、1–6 碼）、目前檔名（原樣 / 大寫 / 小寫）、
    日期時間（拍攝 / 修改 / 今天，多種格式）、中繼資料（相機、鏡頭、ISO、焦距、光圈、快門、評等、標籤）、字串替代
  - 在 XMP 中繼資料中保留目前的檔名（xmpMM:PreservedFileName，與 Bridge 相同）
  - 相容性：Windows / Mac / Unix 不合法字元自動處理
  - 即時預覽每一張的新檔名，新檔名重複時會提醒並禁止執行
  - 安全：先檢查所有衝突，有問題就完全不動；以兩階段改名，名稱互換也不會出錯，失敗時自動還原

## 幻燈片（v0.3）

左側「小日子寫真館」右邊的「▶ 幻燈片」或按 **P**（Mac 選單：檔案 → 播放幻燈片 ⇧⌘P）直接全螢幕播放；播放選項在「⚙ 系統設定」右欄的「幻燈片選項」，改了會記住：

| 設定 | 選項 |
|---|---|
| 播放範圍 | 目前顯示的照片（會套用左側篩選，例如只播 4 星以上）／只播已選取的照片；可略過拒絕的照片 |
| 順序 / 起點 | 依目前排序或隨機；從第一張或從目前選取的照片開始 |
| 每張秒數 | 2–15 秒 |
| 轉場 | 淡入淡出、緩慢推近（Ken Burns，每張隨機推近位置）、無 |
| 其他 | 循環播放、全螢幕、顯示檔名與評等 |
| 背景音樂 | 加入多首本機音樂（MP3、M4A/AAC、WAV、AIFF、FLAC），依序播放、可調整順序與音量；開始與結束會自動淡入淡出 |
| 依音樂長度 | 自動計算每張秒數，讓照片與音樂一起結束（音樂太短會重複播放，太長則在最後淡出） |

播放中：**Space** 暫停／繼續（音樂一起暫停）、**← →** 上一張／下一張、**M** 靜音、**I** 顯示資訊、
**F** 切換全螢幕、**Esc** 結束（回到目前這張照片）。播放時也能按 **0–5 / X / 6–9** 直接評分，
適合和客人一起看照片時邊看邊挑。設定與音樂清單會被記住，下次直接使用。

> 音樂檔只在本機讀取，完全離線。程式只能讀取你在對話框中選擇的音樂檔，不會存取其他檔案。

## 為什麼快：架構說明

```
前端 (TypeScript, 虛擬化格子)                 後端 (Rust)
<img src="img://localhost/t/<session>/<id>">  ──►  自訂協定 img://
                                                    │ 1. 記憶體 LRU 命中 → 立即回應
set_viewport(可見的 id)  ──────────────────►        │ 2. 進入工作佇列（快速小縮圖 > 預覽 > 縮圖，畫面左上到右下）
                                                    │ 3. 工作者取出時若已捲出畫面 → 410 取消
                                                    │ 4. SQLite 磁碟快取命中 → 回應
                                                    │ 5. 產生縮圖：
                                                    │    RAW → 走 TIFF IFD 找內嵌 JPEG（mmap，只讀需要的頁）
                                                    │    JPEG → DCT 縮放解碼（直接解成 1/2、1/4、1/8）
                                                    │    套用 EXIF 方向 → 編碼 → 寫入快取
set_order(排序後的全部 id) ─────────────────►       │ 6. 佇列空閒時依排序在背景預先產生其餘縮圖
```

1. **內嵌預覽優先**：RAW 幾乎都內嵌了相機算好的 JPEG；相機直出的 JPEG 也常在 MPF 區段附了一張約 1616×1080 的預覽
   （Sony / Canon / Nikon）。做縮圖時只讀這張預覽：5000 萬畫素、22MB 的 JPEG 只需讀約 0.8MB，速度快約 19 倍。
   挑「長邊 ≥ 需求中最小的一張」來解碼，完全不做解馬賽克
   （`src-tauri/src/jpeg.rs`、`tiff.rs`）。
2. **DCT 縮放解碼**：解 400px 縮圖時，JPEG 直接以 1/8 尺寸解碼，省下大量 CPU 與記憶體（`render.rs`）。
3. **可取消的優先佇列**：畫面上的格子依左上到右下的順序先處理，捲出畫面的工作直接丟棄（`core.rs`）。
3. **快速小縮圖**：第一次顯示時先取檔案內嵌的約 160px 縮圖（約 1 毫秒，自動裁掉黑邊、修正壓扁的比例並轉正），
   畫面幾乎立刻填滿；正式縮圖算好再無縫換上。有調整設定的照片不用小圖（看不出調整效果）。
3. **背景預先產生**：畫面上的縮圖好了之後，依目前的排序從畫面後面開始，把整個資料夾的縮圖預先產生進磁碟快取
   （最多用一半的工作執行緒），之後捲到哪裡都已經有圖。
4. **兩層快取**：記憶體 LRU（3000 張縮圖 + 24 張預覽）＋ SQLite 持久化快取，鍵值為路徑 + 修改時間 + 大小（`cache.rs`）。
5. **中繼資料非同步**：先列出檔案讓畫面立刻出現，EXIF / 評等在背景分批讀取後推送給前端；
   只用 2 個執行緒，畫面上的縮圖還在產生時先讓路（不跟縮圖搶 CPU 與外接硬碟）。
6. **虛擬化 + 物件池**：DOM 裡只有畫面上下幾列的格子，捲動時重複使用。
7. **全螢幕預先載入**：前後各兩張的預覽先載好，翻頁幾乎零等待。

### 模糊偵測原理

拉普拉斯變異數（Variance of Laplacian）：把影像切成 4×4 區塊，各自計算後取最高的兩塊平均，
所以「主體清楚、背景散景」的照片不會被誤判。分數是相對的：低於該資料夾中位數 35% 的照片才標為「可能模糊」（`blur.rs`）。

## 已知限制

- RAW 只顯示內嵌預覽，沒有自行做 RAW 顯像；沒有內嵌預覽的 RAW 會顯示格式佔位圖。
- HEIC / AVIF 需要 libheif，目前只有在檔案內含 JPEG 縮圖時才能顯示。
- 尚未做色彩管理（ICC），廣色域照片的顏色可能偏淡。
- 閉眼判斷需要臉部至少約 40px（分析解析度 2048px 下）；更小的臉只會偵測、不判斷眼睛。
- 側臉超過約 60°、戴墨鏡、臉被遮住一半時，閉眼分數不可靠。
- 新生兒模式是整個資料夾一起忽略閉眼；若同一組照片裡有爸媽入鏡，爸媽的閉眼也不會被標記。
