# Photo Selector

專為攝影師「選片」設計的照片瀏覽工具（Rust + Tauri 2）：打開上萬張的資料夾不卡、純鍵盤評分，
並自動抓出**閉眼、模糊、主體失焦**的照片。新生兒寫真可切換成「忽略閉眼」模式。

> 本專案是獨立開發的軟體，與 Adobe 無關，介面與名稱皆為自有設計。

## 開發環境

需求：Rust（stable）、Node.js 18+，以及 Tauri 的系統套件
（Linux 需要 `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev`，見 <https://tauri.app/start/prerequisites/>）。

```bash
npm install
npm run tauri dev                       # 開發模式
npm run tauri dev -- -- /path/to/photos # 啟動時直接開某個資料夾
npm run tauri build                     # 打包安裝檔
cargo test --manifest-path src-tauri/Cargo.toml   # 後端單元測試
```

## 選片分析（v0.2）

開啟資料夾後會在背景自動分析（也可以按工具列的「選片分析」），每張照片檢查：

| 檢查項目 | 標記 | 說明 |
|---|---|---|
| 閉眼 | 🟥 `閉眼 2/6` | 6 個人裡有 2 個閉眼 |
| 半閉眼 | 🟧 `半閉 1/6` | 瞇眼、低頭看東西、眨眼到一半，建議人工確認 |
| 整張模糊 | 🟥 `模糊` | 手震或完全沒對到焦 |
| 主體失焦 | 🟧 `主體失焦` | 整張不糊，但主角（最大的那張臉）不清楚，焦點跑到背景 |

- 左側「選片建議」可直接篩出 **建議淘汰** / **需要確認** / **沒有問題**；也能依「眼睛」、「清晰度」篩選。
- 「將建議淘汰標為拒絕」一鍵把有問題、且**尚未評分**的照片標為拒絕（已評星的不會被動到）。
- 全螢幕預覽（Space）會在每張臉上畫框：綠＝睜眼、橘＝半閉、紅＝閉眼，並顯示分數；按 **F** 開關。

### 拍攝類型：新生兒模式

工具列「拍攝類型」選 **新生兒（忽略閉眼）** 時，不再標記閉眼 / 半閉眼（新生兒大多在睡覺），
但**仍會檢查模糊與主體失焦**（寶寶的臉有沒有對到焦依然重要）。設定會依資料夾記住，
新的資料夾預設沿用上次的選擇。切換模式是即時的，不需要重新分析。

### 運作原理

1. **人臉偵測**：MediaPipe BlazeFace。原模型只擅長近距離大臉，所以把照片切成多層互相重疊的方塊
   （整張 → 短邊 → 1/2 → 1/4）分別偵測，再以加權 NMS 合併——合照裡的小臉也找得到。
2. **誤判過濾**：偵測器分數與特徵點模型的「是否為臉」分數都要夠高才採用（可排除金屬罐、圖案等）。
3. **閉眼分數**：依兩眼連線把臉轉正、裁成 256×256，取得 478 個特徵點，再交給 blendshape 模型
   算出 `eyeBlinkLeft / eyeBlinkRight`。兩眼平均 ≥ 0.45 為閉眼、≥ 0.28 為半閉。
   比傳統的眼睛長寬比（EAR）更能分辨「閉眼」與「側臉、低頭」。
4. **清晰度**：整張用分區拉普拉斯變異數；主角臉部則裁出臉部、縮放到固定大小後計算。
   兩者都採**相對門檻**：低於該資料夾中位數的 35% 才標記，不受相機、場景差異影響。
5. 推論使用純 Rust 的 [tract](https://github.com/sonos/tract)，模型內嵌在執行檔中，不需安裝任何額外元件。
   結果存入 SQLite 快取，重新開啟資料夾不必重算。

### 驗證結果

用一張 6 人合照（含大笑瞇眼、低頭看牌）比對 MediaPipe 官方 Python 版：

| 人物狀態 | 官方版分數（左 / 右） | 本程式 | 判定 |
|---|---|---|---|
| 笑到眼睛幾乎閉上 | 0.62 / 0.55 | 0.65 / 0.50 | 閉眼 ✓ |
| 大笑瞇眼 | 0.66 / 0.31 | 0.70 / 0.29 | 閉眼 ✓ |
| 低頭看牌 | 0.36 / 0.34 | 0.45 / 0.42 | 半閉 ✓ |
| 其餘三人睜眼 | < 0.25 | < 0.23 | 睜眼 ✓ |

官方版的偵測器在這張合照裡找不到任何臉；本程式的分層偵測找到全部 6 張。
效能：每張照片約 0.8 秒（單核心，2048px），多核心並行處理，估計 1000 張約 2–3 分鐘（8 核心，尚未用大量實拍照片實測）。

> 判斷是輔助性質，不會自動刪除或拒絕任何照片。門檻是依少量樣本調整的，實際拍攝資料若有誤判，
> 可調整 `src-tauri/src/face.rs` 的 `CLOSED_THRESHOLD` / `HALF_THRESHOLD`。

| 檔案操作 | 選取項目複製 / 移動到其他資料夾（連同配對檔與 .xmp，不覆蓋同名檔），跨磁碟移動、保留修改時間 |

## 為什麼快：架構說明

```
前端 (TypeScript, 虛擬化格子)                 後端 (Rust)
<img src="img://localhost/t/<session>/<id>">  ──►  自訂協定 img://
                                                    │ 1. 記憶體 LRU 命中 → 立即回應
set_viewport(可見的 id)  ──────────────────►        │ 2. 進入工作佇列（預覽高優先、縮圖低優先，LIFO）
                                                    │ 3. 工作者取出時若已捲出畫面 → 410 取消
                                                    │ 4. SQLite 磁碟快取命中 → 回應
                                                    │ 5. 產生縮圖：
                                                    │    RAW → 走 TIFF IFD 找內嵌 JPEG（mmap，只讀需要的頁）
                                                    │    JPEG → DCT 縮放解碼（直接解成 1/2、1/4、1/8）
                                                    │    套用 EXIF 方向 → 編碼 → 寫入快取
```

1. **內嵌預覽優先**：RAW 幾乎都內嵌了相機算好的 JPEG。挑「長邊 ≥ 需求中最小的一張」來解碼，完全不做解馬賽克
   （`src-tauri/src/jpeg.rs`、`tiff.rs`）。
2. **DCT 縮放解碼**：解 400px 縮圖時，JPEG 直接以 1/8 尺寸解碼，省下大量 CPU 與記憶體（`render.rs`）。
3. **可取消的優先佇列**：LIFO 讓最新捲到的畫面先處理，捲出畫面的工作直接丟棄（`core.rs`）。
4. **兩層快取**：記憶體 LRU（3000 張縮圖 + 24 張預覽）＋ SQLite 持久化快取，鍵值為路徑 + 修改時間 + 大小（`cache.rs`）。
5. **中繼資料非同步**：先列出檔案讓畫面立刻出現，EXIF / 評等在背景分批讀取後推送給前端。
6. **虛擬化 + 物件池**：DOM 裡只有畫面上下幾列的格子，捲動時重複使用。
7. **全螢幕預先載入**：前後各兩張的預覽先載好，翻頁幾乎零等待。

### 模糊偵測原理

拉普拉斯變異數（Variance of Laplacian）：把影像切成 4×4 區塊，各自計算後取最高的兩塊平均，
所以「主體清楚、背景散景」的照片不會被誤判。分數是相對的：低於該資料夾中位數 35% 的照片才標為「可能模糊」（`blur.rs`）。

```
src/                    前端（Vite + TypeScript，無框架）
  main.ts               狀態、篩選排序、全螢幕、比較、快捷鍵
  cull.ts               選片分析結果判讀、拍攝類型、人臉框
  grid.ts               虛擬化縮圖格
  api.ts                後端指令與型別
src-tauri/src/
  lib.rs                Tauri 指令與 img:// 協定註冊
  core.rs               工作階段、優先佇列、可視範圍取消、記憶體快取
  render.rs             縮圖 / 預覽 / 原圖產生、方向校正
  jpeg.rs               內嵌 JPEG 搜尋與驗證（排除無損 JPEG 的 RAW 資料）
  tiff.rs               TIFF IFD 走訪（RAW 預覽位置、方向、CR3 box）
  meta.rs               EXIF 讀取
  xmp.rs                XMP 評等 / 標籤讀寫（保留其他內容）
  scan.rs               資料夾掃描、RAW+JPEG 配對
  blur.rs               清晰度評分
  face.rs               人臉偵測、特徵點、閉眼分數、臉部清晰度（tract + ONNX）
src-tauri/models/       MediaPipe 人臉模型（ONNX，Apache 2.0）
  cache.rs              SQLite 快取
  ops.rs                複製 / 移動
```

## 已知限制

- JPEG 的評等也寫在 `.xmp` 附屬檔。Lightroom / Bridge 讀 RAW 的附屬檔，但 JPEG 只讀檔案內嵌的 XMP，
  所以在本程式評的 JPEG 星等，Adobe 軟體目前看不到（規劃中：可選擇寫入 JPEG 內嵌 XMP）。
- RAW 只顯示內嵌預覽，沒有自行做 RAW 顯像；沒有內嵌預覽的 RAW 會顯示格式佔位圖。
- HEIC / AVIF 需要 libheif，目前只有在檔案內含 JPEG 縮圖時才能顯示。
- 尚未做色彩管理（ICC），廣色域照片的顏色可能偏淡。
- 閉眼判斷需要臉部至少約 40px（分析解析度 2048px 下）；更小的臉只會偵測、不判斷眼睛。
- 側臉超過約 60°、戴墨鏡、臉被遮住一半時，閉眼分數不可靠。
- 新生兒模式是整個資料夾一起忽略閉眼；若同一組照片裡有爸媽入鏡，爸媽的閉眼也不會被標記。
